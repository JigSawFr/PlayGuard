# 故障排除

重新进入被锁定的主机、报告问题，以及开发者模式。返回 [README](../../README.md)。

## 被锁在外面？

PlayGuard 只能看到它所运行的系统的家长控制：**emuMMC 和 sysMMC 各有各的设置**（在一个系统上删除的 PIN，在另一个系统上仍然存在）。需要修复哪个系统，就在哪个系统上运行它。

### 二手主机

你知道 PIN，但前任主人的手机应用仍然关联着（解除关联失败，或者恢复出厂设置时要求输入他们的账号）。

*PIN › 解除手机应用的关联*，然后，如果你完全不想要家长控制，再选 *删除所有家长控制*。两者都可以离线使用，在 emuMMC 和 sysMMC 上都一样。

### 忘记了 PIN

*显示PIN* 本身就要求输入 PIN，所以这里帮不上忙。如果安装了恢复 sysmodule（见下文），放一个 `RESCUE` 文件并重启：恢复画面会设置一个新的 PIN（它从不显示旧的）。如果没有安装，*删除所有家长控制* 可以从头开始（会先保存一份设置备份；备份从不包含 PIN）：如果开启了 *用PIN保护PlayGuard*（默认为 *更改前*），请先把 SD 卡插到电脑上，在 `sd:/config/playguard/config.json` 中把 `"pin_lock"` 设为 `"off"`。

### 游戏时间阻止了一切（限制为 0 分钟），而且忘记了 PIN

这时 PlayGuard 本身无法启动。请**事先**安装可选的恢复 sysmodule（`playguard-rescue.zip`）；被锁在外面时，在 SD 卡上放一个空的 `config/playguard/RESCUE` 文件并启动主机——它会解除主机的锁定，让 PlayGuard 能够打开。见 [`sysmodule/README.md`](../../sysmodule/README.md)（英文）。

这个模块必须与 PlayGuard 的版本一致：每次更新 PlayGuard 后，重新解压该版本的 `playguard-rescue.zip`（或者在通知铃铛的 *恢复 sysmodule 不是最新版本* 上选择 *更新*），然后重启主机。较旧的模块留下的报告 PlayGuard 无法核验：这时恢复画面不提供任何操作，会说明模块较旧，再次使用 `RESCUE` 也是同样的结果，直到它被更新。

### 主机未破解

PlayGuard 帮不上忙：它需要 Atmosphère。任天堂客服的主密钥（master key）流程是官方的解决办法。

## 报告问题

出错时会显示系统的代码（例如 `0x0001088E`）以及关于它的已知信息：对于含义已有记录的代码，会说明该怎么做；否则，一份报告会有帮助。

1. *关于 › 帮助与诊断 › 导出诊断报告* 会在 `sd:/config/playguard/logs/reports/` 中保存一个文本文件：系统版本、Atmosphère 版本、启动用了多长时间以及较慢的画面用了多长时间（更改历史、*所有游戏*、已安装游戏的检查、会自动刷新的标签页）、时钟、存储、序列号隐藏和游戏补丁的状态、每次家长控制查询的原始结果，以及日志：上次运行是如何结束的、剩余的内存和 SD 卡空间、最新的崩溃文件和最后记录的 80 行。**它从不包含 PIN 或序列号**。
2. [提交一个 issue](https://github.com/JigSawFr/PlayGuard/issues/new) 并附上它。

或者，在主机联网时，*关于 › 帮助与诊断 › 在线发送报告*（开发者模式下在诊断报告上按 Ⓧ）会把它发送出去，同时附上最新的崩溃报告（`logs/crashes/` 中 PlayGuard 的最后 3 份，以及 `sd:/atmosphere/crash_reports/` 中 Atmosphère 在过去一周内记录的自制软件崩溃的最后 2 份：其中可能有其他自制软件的崩溃，发送前显示的列表会说明是哪个）、本次和上一次运行的日志（`logs/sessions/`；较长的日志：开头部分和最后 64 KiB）以及调试文件（游戏时间数据块的参照、开启 *记录游戏时间* 时游戏时间记录的结尾部分、更改历史中最近 20 项更改（不含名称（游戏、用户或配置的名称），只保留日期），以及 PlayGuard 的设置），发送到你 GitHub 账户中的一个秘密 gist（报告和每个文件各作为一个单独的文件；未登录时，PlayGuard 会先提示登录；登录后，紧接在下方的 *GitHub 账户* 可以退出登录；GitHub 拒绝 gist 时，PlayGuard 会提示重新登录），发送前会准确说明要发送哪些内容。它会显示链接和两个二维码：报告，以及已预先填好链接、你的版本、PlayGuard 的启动方式（在游戏之上还是从相册；请补充是哪个菜单）和系统（sysMMC 或 emuMMC）的问题报告表单。在你于 GitHub 上删除 gist 之前，任何拿到链接的人都能阅读报告，用它提交的问题报告也是公开的：确认时会说明这一点。每个链接都以网络快捷方式（`.url`）保存在 `logs/uploads/` 中，电脑可以用浏览器打开。之前保存在 `logs/reports/` 中的报告也可以用同样的方式发送。

### PlayGuard 在 SD 卡上保存的内容

全部位于 `sd:/config/playguard/logs/`，都是电脑可以打开的纯文本：

- `sessions/session_<date>.txt`——**每次运行一个文件**：PlayGuard 记录的所有内容（以前只能通过 nxlink 传到电脑上），每一行带有时间和级别（`E` 错误、`W` 警告、`I` 信息），最后一行说明这次运行是如何结束的：`=== end: clean exit ===`，或 `=== end: crash, see logs/crashes/… ===`。文件达到 1 MiB 后不再增长。
- `crashes/crash_<date>.txt`——**每次崩溃一个文件**，第一行说明发生了什么：
  - **CPU 异常**（错误的指针、未定义的指令、栈溢出）：故障类型和它访问的地址、调用栈（backtrace）和寄存器。地址是 `playguard.nro` 内的偏移（`playguard+0x1a2b3c`）：该构建的链接映射（它的 CI 运行中的 `-linker-map` 产物）可以查出对应的函数。之后 PlayGuard 像以前一样结束：主机显示错误画面，Atmosphère 自己的报告保存在 `sd:/atmosphere/crash_reports/` 中；
  - **未捕获的异常**：它的类型和消息，以及调用栈；
  - **没有结束的运行**：在下次启动时发现，即上次运行的会话文件没有结束行（PlayGuard 无法捕获的崩溃、卡住时从 HOME 菜单关闭，或者主机被关机），附上那次运行的最后 60 行。

  PlayGuard 运行期间捕获的崩溃文件，末尾附有崩溃前最后记录的 80 行。
- `reports/`、`uploads/`、`play_timer/`——已保存的报告、在线发送的报告的链接、游戏时间记录。

*关于 › 帮助与诊断* 可以设置保留多少份报告、崩溃文件、会话日志和链接（每个文件夹分别设置；最新的一份始终保留）。

## 开发者模式（研究新的系统版本）

在 *关于 › 版本* 上按 Ⓨ 七次；开发者工具会出现在 *关于 › 帮助与诊断* 的末尾。它增加了：

- 一个**只读**开关——开启后，应用无法更改任何东西：这是研究新系统版本的安全方式（系统版本画面会直接提供这个选项）；
- 在画面上查看诊断报告（Ⓨ 保存，Ⓧ 在线发送），以及在游戏时间标签页中导出它的快捷方式；
- 原地**安装其他构建**，在修复发布之前先测试：最近 20 个发布版本之一（包括预发布，带有标签）、`main` 最近 20 个提交之一，或者本仓库某个分支上打开的拉取请求的最新构建（从不来自 fork：它的代码还没有经过审查），每一类各在一个标签页中（Ⓛ / Ⓡ 显示在标签页两侧，用于切换；画面打开时显示已安装构建所在的标签页，每个标签页都会统计比已安装构建新的构建数量）。每个构建在标签上方显示它的标题（提交或拉取请求的主题；提交的完整消息是它的描述）：更改的类型（*新功能*、*修复*、*文档*…）和范围、*不兼容*、提交来自的拉取请求、检查的结果（*CI 通过*、*CI 失败*、*CI 进行中*）、预发布、*已安装* 或 *较新*；右侧显示它有多旧以及它的提交。在拉取请求标签页上（显示时），A 会反过来排序（最新的构建在前，或按编号）。构建会先打开它的页面：标签（类型、检查、已安装或较新）、一张信息卡片（构建时间、大小、提交、校验和、GitHub 何时删除它）、**安装**、**在 GitHub 上查看**（它的页面以二维码显示，供手机扫描），然后是发布版本的说明或拉取请求的描述，按 GitHub 的 Markdown 绘制（标题、列表、任务框、代码、引用和提示、表格）。来自 GitHub 的一切都以纯文本显示：不打开任何链接，不运行任何 HTML 或脚本，并会去除可能伪装标题的不可见字符（从右到左覆盖字符、零宽字符、控制字符、无效的 UTF-8）。登录后，Ⓨ（*搜索*）可以输入拉取请求的编号（打开或已关闭的）或提交（7 到 40 位十六进制数字）来查找它的构建，只限本仓库的分支。发布版本不需要任何条件；其他的是构建工作流的产物，GitHub 只提供给已登录的用户：**GitHub 账户** 通过一个代码和一个供手机扫描的二维码登录（唯一请求的权限是读取构建工作流的文件（Actions）和创建 gist，用于 *在线发送报告*；除此之外，令牌只能读取公开内容；它保存在 `github_token` 中，从不随报告发送，*GitHub 账户* 可以退出登录）。PlayGuard 下载构建，进行检查（大小、GitHub 记录的 SHA-256、NRO 文件头），用它替换自己的 `.nro`，然后以它重新启动（只要设置了 PIN，就会先要求输入）。列表保留 10 分钟，打开时立即显示，并标明它有多旧（Ⓧ 重新获取）；获取期间，进度条显示进度。中途断开的下载（网络中断），下次安装同一个构建时会从中断处继续。被替换的构建会保留（`playguard.nro.previous`）：同一列表中的**回到上一个构建**会把它们再换回来。如果从这里（或通过 *更新方式* 中的“在 PlayGuard 内”）安装的构建在显示第一个画面之前崩溃，PlayGuard 下次启动时会在一个纯文本画面上提示回到上一个构建，在加载任何其他内容之前（A 回到上一个，B 仍然启动它），不需要 PIN，因为崩溃的可能正是 PIN 画面本身。其他任何时候，*回到上一个构建*（见上）都可以做到，需要输入 PIN。同一个列表随时可以回到任何一个发布版本；开发者模式下，*关于 › 版本* 会显示提交。每个画面的标题栏在标题旁显示正在运行的版本：发布版本显示在灰色标签中（`1.2.0`），其他构建显示在琥珀色标签中并附上提交，这样测试构建永远不会被误认为发布版本。产物在 90 天后过期；
- **比较游戏时间数据块**（仅在手机应用已关联并且能够同步时——用 hosts 文件拦截任天堂时不行；*PIN* 中也有），用于解析 PlayGuard 尚未显示的设置：把原始数据块保存为参照，在手机应用中更改一项设置，然后回来——PlayGuard 会列出发生变化的值（按需保存在 `logs/reports/` 中）。在手机应用中设置的每天不同的就寝时间，可以用这种方法确认。把这个文件附到 issue 中，或者和报告一起发送（*在线发送报告*）。
- **记录游戏时间**：PlayGuard 打开期间每 30 秒在 `logs/play_timer/log.csv` 中记录一行游戏时间计时器报告的内容（剩余时间、已用时间、原始设置数据块…），这是可以直接用电子表格打开的文件；PlayGuard 每次更改之后也会立即记录一行，说明是哪项更改（它的最后一列 `event`），时钟变化超过实际经过的时间时还会加上一条备注。开着它跨过午夜，或者直到时间用完，它能显示一份报告无法显示的东西：已用时间何时重置，主机在快结束时说了什么。这个开关会被记住；它只在开发者模式下记录。目前已知的情况见 [parental-controls.md](../parental-controls.md)（英文）。
- **清除缓存**和**删除日志文件**，各自在确认后执行，确认时会说明有多少个文件、占用多少空间：缓存（`cache/` 和每个系统的 `nand/<system>/cache/`：游戏名称和图标、游玩记录的最新数据、构建列表）需要时会从主机重新读取；日志文件包括崩溃文件、会话日志（本次运行正在写入的除外）、已保存的报告和游戏时间记录，而 `uploads/`（在线发送的报告的删除链接）和数据块参照会保留。设置、历史记录、备份、配置和导出文件从不受影响。
- **帧统计**：每秒在 `logs/frame_stats.txt` 中记录一行，包括绘制画面所用的时间和迟到的帧，用于在主机上比较不同画面的表现。**背景光晕**可以关闭画面后方的柔和光效（这时这一行的模式会以 `-noglow` 结尾），以衡量它的开销。
