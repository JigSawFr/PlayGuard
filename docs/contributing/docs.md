# The user guide and the website

Part of the [contributor's guide](../../CONTRIBUTING.md).

When a change is visible to users, update the English and French pages **both**. The [README](../../README.md) is in English only and stays short: the pitch, the main features, install and links to the website, where parents read the documentation in their language (the app's links to it are `app::doc_url()`: an installed app keeps them, so a page or a heading it links to keeps its name, which `tools/check_resources.py` checks); the details go to the user guide in [`docs/`](../../docs/), the website's source — `getting-started.md` (the walk-through and the everyday tasks, a parent's first page), `features.md` (every tab and setting), `install.md`, `compatibility.md`, `troubleshooting.md` (locked out, the common problems, reporting a bug) — with its French version in [`docs/fr/`](../../docs/fr/) and the console's other languages in `docs/<language>/`.

Those other translations may lag: after changing an English page, stamp the French one again (`python3 tools/doc_stamp.py docs/fr/<page>.md`); `python3 tools/doc_delta.py docs/<language>/<page>.md` shows what changed in the English page since its translation was stamped (the diff from the version the stamp names), and `--all` lists every translation that is behind (CI's `host-tests` job runs it with `--github` for every pull request: a warning on each English page with translations behind, naming their languages, never a failure); the others say on the website that the English page may be more recent until someone updates and stamps them.

`python3 tools/check_site_links.py <site-dir>` checks every link of a built site, its links out and its pages' policy (boreale-site's checks; CI runs it). boreale-site's `library/boreale-site/tools/site_layout.py <site-dir>` (Playwright) checks its layout on a phone, a tablet and a desktop, and with `SITE_AXE=<axe-core's axe.min.js>` its accessibility (CI runs both for a pull request that changes the site, the layout with the options of `.github/workflows/web.yml`).

The reference pages (`config.md`, `parental-controls.md`, `companion-app.md`) are in English only, but for `themes.md`, also a reference page of the website, whose French version is in `docs/fr/`. The Home Assistant guide (`home-assistant.md`, in French `home-assistant.fr.md`, beside it) and the remote link's design and protocol (`sync-design.md`, `sync-protocol.md`) are not on the website either: a link to them opens them on GitHub. [`hardware-test.md`](../../docs/hardware-test.md), the checklist to go through on a console, is for contributors: in English and French only, it is not on the website (not in `tools/build_site.py`'s `DOCS`), so a guide's link to it opens it on GitHub.

The README's screenshots (`images/screenshots/*.png`, which the tour `images/video/playguard-tour.*`, the website's English pages without their own and the Homebrew App Store's listing show too) come from the desktop build: `make desktop`, then `xvfb-run -s "-screen 0 1280x720x24" python3 tools/readme_screenshots.py [screen…]` (Xvfb, xdotool, ImageMagick, dbus and faketime), on the smoke test's console at 16:00 in the dark theme, with the latest release's badge (`README_SHOTS_VERSION=1.3.0` for the release about to be made); then `python3 tools/readme_screenshots.py clips` for the tour's moving screens (`images/screenshots/clips/*.webm`: Today, the child view, a day edited, filmed with ffmpeg's x11grab while their keys are pressed) and `node tools/render_tour.mjs` for the tour (`playguard-tour.mp4` and `.gif`, and `playguard-teaser.mp4`, the same in under half a minute), whose texts are the site's catalogs' `tour_*` keys (`site/i18n/`, `**…**` the words in colour) and whose music is `branding/tour-music.m4a` (CC BY 4.0, credited on its last screen and in `branding/tour-music.txt`); the tour also shows `extra_time`, `child_view`, `notifications`, the release notes (`notes_*`, on a console behind on everything), `installed_games`, the forwarders (`forwarders`, `forwarder_protection`, `homebrew_menu`) and the gate's screens (`gate`: `make gate-preview`'s, copied as `gate_*.png`). A screen to try keys out: `<name>=<language>:<tab>:<key>,<key>…[:<SIM>=<value>;…]` (a `PLAYGUARD_SIM_` variable without its prefix; `UPDATES=1` the console behind on everything), which prints where the focus ended (`README_SHOTS_OUT=<dir>` to keep it out of the repository). Take them again when a change alters one of those screens; the website's, in every language, are taken by CI (`site/README.md`).
